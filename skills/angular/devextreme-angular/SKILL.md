# DevExtreme Angular

## Purpose

Wire DevExtreme widgets into Angular with exact version pinning, server-side data operations that the backend really implements, and license handling that keeps keys out of public source. A good DataGrid: `remoteOperations` matches the API, the `CustomStore` maps `loadOptions` to an allowlisted query, totals are correct, and edits surface server errors.

## When to Use

- Adding or changing `dx-data-grid`, `dx-tree-list`, forms, or other `devextreme-angular` components.
- Implementing `CustomStore` for a REST API, server paging/sorting/filtering.
- Configuring editing, master-detail, export, virtual scrolling.
- Setting up themes, localization, or the DevExtreme license key.

Do not use when: the project uses ng-zorro or Angular Material tables (see the `ng-zorro` skill). Do not introduce DevExtreme into a project that does not already license it.

## Workflow

1. **Detect.**
   - `package.json`: `devextreme`, `devextreme-angular`, `@angular/core`. DevExtreme does not follow semantic versioning; both packages must be the same exact version (official install uses `--save-exact`).
   - Check `angular.json` `styles` for the theme CSS (`dx.fluent.*`, `dx.material.*`, or legacy `dx.light.css`).
   - Look for `devextreme-license.ts` / a `prebuild` script running `devextreme-license`, and `config({ licenseKey })` in `main.ts`.
   - Standalone vs NgModule, zoneless (v21+ default), `OnPush` (v22 default), and existing grid conventions (`dxo-data-grid-*` vs legacy `dxo-*` nested tags).
2. **Version notes.**
   - Standalone component imports: v26 docs show `DxButtonComponent` from `devextreme-angular/ui/button`; modules (`DxDataGridModule`) still work in standalone components. Follow the existing file. Per-component standalone exports first shipped in an earlier 24.x/25.x release [VERIFY exact version].
   - Nested options: current docs use widget-prefixed tags (`dxo-data-grid-editing`, `dxi-data-grid-column`). Older code uses `dxo-editing`/`dxi-column`; keep whichever the file uses, do not mass-rename [VERIFY whether legacy tags are deprecated in your major].
   - Licensing: v26.1 introduced a new runtime key format generated by the `devextreme-license` CLI; projects already on that flow need no code change. Earlier majors used a key pasted from the DevExpress portal [VERIFY for 24.2/25.x].
   - Excel export: v26 docs use `devextreme-exceljs-fork`; older projects use `exceljs`. Keep what is installed.
3. **Decide data strategy.** Small static lists: plain array. Server data: `CustomStore` with `remoteOperations` limited to what the endpoint supports. Backend on ASP.NET with `DevExtreme.AspNet.Data`: use its `createStore` helper instead of hand mapping.
4. **Implement** with typed rows, explicit `key`, and server-side validation of every sort/filter field.
5. **Verify.** `ng build` (license warning absent in production build), test paging/sorting/filtering against the real or mocked API, test edit conflict and network errors.

## Best Practices

- Pin `devextreme` and `devextreme-angular` to the same exact version; upgrade them together.
- Always set `key` on the store (or `keyExpr` on the grid for arrays). Editing, selection, and master-detail depend on it.
- Enable only the remote operations the backend implements: `<dxo-data-grid-remote-operations [paging]="true" [sorting]="true" [filtering]="true">`. Mixing remote paging with client filtering gives wrong results.
- Return `totalCount` only when `loadOptions.requireTotalCount` is true, `groupCount` when `requireGroupCount` is true.
- Translate `loadOptions.filter` into the API's own query format with an allowlist of fields and operators. Never pass the raw array to a SQL/ORM layer.
- Use `lastValueFrom(http.get(...))` in `CustomStore.load` so `HttpClient` interceptors (auth, errors) still apply.
- Throw (or reject) with a readable message on failure; the grid shows its load-error panel.
- Editing: implement `insert`, `update`, `remove` in the store; `update(key, values)` receives only changed fields, so send a PATCH. Map 409/422 to a rejected promise with a message the grid can show.
- Large datasets: `remoteOperations` plus `<dxo-data-grid-scrolling mode="virtual">`; set fixed column widths, avoid `columnAutoWidth`, use `renderAsync` for heavy cell templates, use deferred selection.
- Master-detail: fetch detail data lazily per expanded row, not with the master query.
- Export: run in `onExporting`; for remote data, the grid loads all filtered rows, so cap or move large exports to a server endpoint.
- Theme: one theme CSS in `angular.json` `styles`; current docs use `dx.fluent.blue.light.css`. Switching families (generic/material/fluent) is a visual change, not a refactor step.
- Localization: call `loadMessages(...)` and `locale(...)` from `devextreme/localization` before the first widget renders (root component constructor or `main.ts`).
- License: generate the runtime key in `prebuild` via `devextreme-license --out src/devextreme-license.ts --force`, git-ignore the generated file, supply the DevExpress key through a CI secret. DevExpress states the runtime key is not secret and ends up in the bundle, but you must not publish it, so it never belongs in a public repo.

## Anti-patterns

- `remoteOperations: true` with an API that only pages — sorting/filtering silently breaks; enable per operation.
- Loading the full dataset into an array for 100k rows — memory and first render cost; use `CustomStore` with remote paging.
- Forwarding `JSON.stringify(loadOptions.filter)` straight to the database — injection and unbounded queries; allowlist.
- `devextreme@^26.1.0` with `devextreme-angular@26.1.6` — mismatched versions break at runtime; pin both exactly.
- Committing `devextreme-license.ts` or the DevExpress key — license breach; generate in CI from a secret.
- `cellTemplate` for conditional styling — slow; use `onCellPrepared`.
- Renaming all nested `dxo-*` tags in an unrelated change — noise; keep the file's style.

## Implementation Examples

### License and locale bootstrap

```ts
// src/main.ts
import { bootstrapApplication } from '@angular/platform-browser';
import config from 'devextreme/core/config';
import { loadMessages, locale } from 'devextreme/localization';
import deMessages from 'devextreme/localization/messages/de.json';
import { licenseKey } from './devextreme-license'; // generated by prebuild, git-ignored
import { AppComponent } from './app/app.component';
import { appConfig } from './app/app.config';

config({ licenseKey });
loadMessages(deMessages);
locale(navigator.language.startsWith('de') ? 'de' : 'en');

bootstrapApplication(AppComponent, appConfig).catch((err: unknown) => console.error(err));
```

### CustomStore with remote paging, sorting, filtering

```ts
// src/app/orders/orders.store.ts
import { inject, Injectable } from '@angular/core';
import { HttpClient, HttpParams } from '@angular/common/http';
import { lastValueFrom } from 'rxjs';
import CustomStore from 'devextreme/data/custom_store';
import type { LoadOptions } from 'devextreme/data';

export interface Order { id: number; customer: string; total: number; status: 'open' | 'closed' }
interface OrderPage { items: Order[]; total: number }

const SORTABLE = new Set<keyof Order>(['id', 'customer', 'total', 'status']);
const FILTERABLE = new Set<keyof Order>(['customer', 'status']);

@Injectable({ providedIn: 'root' })
export class OrdersStoreFactory {
  private readonly http = inject(HttpClient);

  create(): CustomStore<Order, number> {
    return new CustomStore<Order, number>({
      key: 'id',
      load: async (opts: LoadOptions<Order>) => {
        const params = toParams(opts);
        try {
          const page = await lastValueFrom(this.http.get<OrderPage>('/api/orders', { params }));
          return { data: page.items, totalCount: opts.requireTotalCount ? page.total : undefined };
        } catch {
          throw new Error('Orders could not be loaded.');
        }
      },
      update: (key, values) => lastValueFrom(this.http.patch<Order>(`/api/orders/${key}`, values)),
      remove: (key) => lastValueFrom(this.http.delete<void>(`/api/orders/${key}`)),
    });
  }
}

function toParams(opts: LoadOptions<Order>): HttpParams {
  let p = new HttpParams();
  if (opts.skip != null) p = p.set('offset', opts.skip);
  if (opts.take != null) p = p.set('limit', opts.take);
  const sorts = Array.isArray(opts.sort) ? opts.sort : opts.sort ? [opts.sort] : [];
  for (const s of sorts) {
    if (typeof s === 'object' && s !== null && 'selector' in s && SORTABLE.has(s.selector as keyof Order)) {
      p = p.append('sort', `${String(s.selector)}:${s.desc ? 'desc' : 'asc'}`);
    }
  }
  // Supports only simple ["field", "=", value] or ["field", "contains", value] filters.
  const f = opts.filter;
  if (Array.isArray(f) && f.length === 3 && typeof f[0] === 'string' && FILTERABLE.has(f[0] as keyof Order)) {
    const [field, op, value] = f as [string, string, unknown];
    if (op === '=' || op === 'contains') p = p.set(`${field}[${op === '=' ? 'eq' : 'like'}]`, String(value));
  }
  return p;
}
```

The `LoadOptions` sort union is broad; the type guards above keep strict mode happy. Combined filters (`[[...], 'and', [...]]`) need a recursive translator; build one only when the grid enables filter row/builder on several columns. The server re-validates every field.

### Grid template

```ts
// src/app/orders/orders-grid.component.ts
import { Component, inject } from '@angular/core';
import { DxDataGridModule, DxTemplateModule } from 'devextreme-angular';
import { DxDataGridTypes } from 'devextreme-angular/ui/data-grid';
import { OrdersStoreFactory } from './orders.store';
import { OrderLinesComponent } from './order-lines.component';
import { exportOrders } from './orders-export';

@Component({
  selector: 'app-orders-grid',
  imports: [DxDataGridModule, DxTemplateModule, OrderLinesComponent],
  templateUrl: './orders-grid.component.html',
})
export class OrdersGridComponent {
  protected readonly store = inject(OrdersStoreFactory).create();
  protected onExporting(e: DxDataGridTypes.ExportingEvent): void { void exportOrders(e); }
}
```

```html
<!-- src/app/orders/orders-grid.component.html -->
<dx-data-grid [dataSource]="store" [showBorders]="true" [columnAutoWidth]="false"
              (onExporting)="onExporting($event)">
  <dxo-data-grid-remote-operations [paging]="true" [sorting]="true" [filtering]="true" />
  <dxo-data-grid-scrolling mode="virtual" />
  <dxo-data-grid-paging [pageSize]="50" />
  <dxo-data-grid-filter-row [visible]="true" />
  <dxo-data-grid-editing mode="row" [allowUpdating]="true" [allowDeleting]="true" />
  <dxo-data-grid-export [enabled]="true" [formats]="['xlsx']" />

  <dxi-data-grid-column dataField="id" [width]="90" [allowEditing]="false" />
  <dxi-data-grid-column dataField="customer" [width]="240" />
  <dxi-data-grid-column dataField="total" dataType="number" format="currency" [width]="140" [allowFiltering]="false" />
  <dxi-data-grid-column dataField="status" [width]="120" />

  <dxo-data-grid-master-detail [enabled]="true" template="lines" />
  <div *dxTemplate="let row of 'lines'">
    <app-order-lines [orderId]="row.data.id" />
  </div>
</dx-data-grid>
```

`dxo-data-grid-scrolling`, `dxo-data-grid-paging`, `dxo-data-grid-filter-row`, and self-closing syntax follow the v26 naming pattern but were not individually confirmed in docs [VERIFY]. On older majors use `dxo-scrolling`, `dxo-paging`, etc. Filtering is disabled on `total` because the store does not translate numeric filters.

## Validation Checklist

- [ ] Detected `devextreme`/`devextreme-angular` exact versions (identical), Angular version, standalone/NgModule, nested tag style.
- [ ] `remoteOperations` lists only operations the API implements; columns with unsupported filters disable filtering.
- [ ] Sort/filter fields allowlisted client-side and validated server-side.
- [ ] `key` set; `totalCount` returned when requested.
- [ ] Load/update/remove errors reject with user-readable messages.
- [ ] Large grids use virtual scrolling with fixed column widths.
- [ ] Export bounded or server-side for large result sets.
- [ ] License key generated at build from a secret; generated file git-ignored; no trial banner in production build.
- [ ] Locale and messages loaded before first widget renders.
- [ ] Build and tests pass.
